# Evidência — KAM-206 (a lista de produtos do painel em 3G simulado)

| Campo | Valor |
|---|---|
| Ticket | KAM-206 — Painel light: o contacto da encomenda ao dono, mascarado e auditado, e a lista de produtos em 3G |
| Ramo | `feature/KAM-206-painel-light` |
| Base | `82e9aa11` (`publico/main`) |
| Data | 2026-11-20 |
| Âmbito deste anexo | O critério 6 do bloco (o critério 9 do KAM-099): a medição antes e depois, o comando, o instrumento e o ambiente |

## 1. O que mudou, e o que se mediu

O KAM-190 mediu a lista de produtos do painel com **200 produtos** em 3G simulado e não cumpriu os
3 s: 1,7 a 4,5 s até o DOM estar pronto, e o peso era de CPU e não de rede. A página tinha um
formulário por produto — 201 `<form>`, 200 `<select>` com três opções e 200 campos de preço.

O KAM-206 tira os formulários da lista. `GET /painel/produtos` passa a ser uma tabela, uma linha por
produto com nome, preço e stock e a ligação para a página dele; **sem guião**. O formulário do preço
e o guião vivem na página de **um** produto, `GET /painel/produtos/:id` (o `get-offer` do COM). O
`PATCH` não mudou.

Mediu-se, na mesma corrida e com o mesmo instrumento, a lista **antes** (os `pagina.ts` e
`rotas.ts` da `publico/main` em `82e9aa11`, montados por cima da árvore), a lista **depois** e a
página de um produto **depois**.

## 2. O perfil

O do KAM-190, sem alteração: o «3G» das DevTools —
`Network.emulateNetworkConditions` com `downloadThroughput` 188 743 B/s, `uploadThroughput`
86 400 B/s, `latency` 562,5 ms, `packetLoss` 0 —, `Emulation.setCPUThrottlingRate` 4 (o perfil
móvel do Lighthouse), cache desligada, um separador novo por corrida. Chromium **156.0.8078.79**
do repositório oficial do Debian (`debian:bookworm-slim`), o mesmo do KAM-190. **Sem compressão**,
como no KAM-190: o `proxy-tls` não tem `encode`. «Interactiva» lê-se como o
`domContentLoadedEventEnd` da `PerformanceNavigationTiming`, que é a leitura do KAM-190; o
`loadEventEnd` vai ao lado.

## 3. Os números (ms, dez corridas por linha)

**Corrida 2: 2026-11-20, 19:57–20:01 UTC, sem contentores de outras sessões à partida** (zero no
`docker ps` antes; dois no fim, de outras sessões, que entraram a meio).

| Página | Octetos | `<form>` | DCL mín. | DCL mediana | DCL máx. | `load` mín. | `load` mediana | `load` máx. |
|---|---|---|---|---|---|---|---|---|
| lista, **antes** | 124 829 | 201 | 1 725 | 2 410 | 7 694 | 3 687 | 5 355 | 11 775 |
| lista, **depois** | 28 630 | 1 | 885 | 1 102 | 1 669 | 967 | 1 103 | 1 676 |
| um produto, depois | 3 911 | 2 | 677 | 872 | 1 389 | 768 | 911 | 1 442 |

**Corrida 1: 2026-11-20, minutos antes da corrida 2 (a hora não se registou), sem registo dos contentores: minutos antes havia *gates* 8 de outras sessões a correr.**

| Página | DCL mín. | DCL máx. | `load` mín. | `load` máx. |
|---|---|---|---|---|
| lista, **antes** | 1 610 | 3 416 | 2 854 | 5 261 |
| lista, **depois** | 990 | 1 250 | 991 | 1 269 |
| um produto, depois | 644 | 996 | 718 | 1 014 |

**Leitura.** Depois, a pior das vinte corridas da lista fica em **1,67 s** até o DOM e **1,68 s**
até ao `load`, e a da página de um produto em **1,44 s**: as três abaixo dos 3 s, nas duas
corridas. A versão antiga reproduz o que o KAM-190 mediu (DCL até 3,4 s numa corrida e 7,7 s na
outra). O corpo desce de 124 529 para 28 330 octetos sem compressão. O «máquina sem carga» do
bloco cumpre-se **à partida** e não ao longo da corrida: a máquina é partilhada, e dois contentores
de outras sessões entraram a meio da segunda. A carga alheia só pode alongar as corridas, e não
encurtá-las, pelo que os números do depois são um tecto e não um piso.

## 4. O comando

Da raiz da árvore, com o `pnpm install` feito (os `node_modules` do `onboarding-web`) e os quatro
ficheiros do §5 numa pasta `<instrumento>`:

```text
docker build -t kamba-m3g-chromium <instrumento>
sh <instrumento>/medir.sh "<arvore>" "<instrumento>" 10
```

O `medir.sh` cria a rede `kamba-m3g`, levanta o Chromium com a CDP na 9222, levanta o painel na
3003 com a árvore (o «antes» monta por cima os dois ficheiros de `<instrumento>/antes/`, tirados
com `git show refs/remotes/publico/main:services/onboarding-web/src/painel/pagina.ts` e o mesmo
para o `rotas.ts`), e corre o condutor na rede do Chromium. Apaga os contentores e a rede no fim.

## 5. O instrumento

`Dockerfile`:

```text
FROM debian:bookworm-slim
RUN apt-get update && apt-get install -y --no-install-recommends chromium socat && rm -rf /var/lib/apt/lists/*
```

`servidor.ts`, que corre num `node:24.21.0-alpine` com a árvore em `/w`:

```ts
// Instrumento do KAM-206: as rotas do painel do onboarding-web, com o COM e o
// canal em memoria e 200 produtos no tenant A, servidas na 3003. Corre de /w (a arvore).
// Escreve a sessao do painel em /m/cookie.txt para o condutor.
import { writeFileSync } from "node:fs";
// Pelo caminho: este ficheiro vive fora da arvore, e a resolucao de um nome nu
// parte do ficheiro que importa, e nao da pasta de trabalho.
import { serve } from "/w/services/onboarding-web/node_modules/@hono/node-server/dist/index.mjs";

import { rotasDoPainel } from "/w/services/onboarding-web/src/painel/rotas.ts";
import { CanalEmMemoria } from "/w/services/onboarding-web/src/painel/canal.ts";
import { ComercioEmMemoria } from "/w/services/onboarding-web/src/painel/comercio.ts";
import { RevogacoesEmMemoria, cunharSessao, novaSessao } from "/w/services/onboarding-web/src/painel/sessao.ts";

const TENANT = "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa";
const CASO = "0a0a0a0a-0a0a-4a0a-8a0a-0a0a0a0a0a0a";
const CHAVE = new Uint8Array(32).fill(7);
const agora = new Date();

const comercio = new ComercioEmMemoria();
comercio.semear(
  TENANT,
  Array.from({ length: 200 }, (_, i) => ({
    sku: `sku-${i}`,
    nome: `Produto com nome longo ${i}`,
    precoTipo: "fixo" as const,
    precoMinor: 1_000_000n,
    currency: "AOA",
    stockModo: "indicativo",
    stockQuantidade: 12,
    stockReservada: 0,
    estado: "publicado",
    versao: "2026-11-02T11:00:00.000001Z",
  })),
);
const casos = new Map([[CASO, { tenantId: TENANT, fase: "activo" }]]);
// As rotas do painel sozinhas: o `createApp` so as monta com a inscricao, e as
// paginas medidas sao as mesmas (o `html` delas poe a CSP e os cabecalhos).
const app = rotasDoPainel({
  comercio,
  canal: new CanalEmMemoria(),
  revogacoes: new RevogacoesEmMemoria(),
  casos: { porId: async (id: string) => casos.get(id) ?? null },
  anelDaAssinatura: [CHAVE, null],
  relogio: () => new Date(),
});
writeFileSync("/m/cookie.txt", cunharSessao(novaSessao(TENANT, CASO, agora), CHAVE));
serve({ fetch: app.fetch, hostname: "0.0.0.0", port: 3003 }, () => console.log("pronto"));
```

`condutor.mjs`, que corre num `node:24.21.0-alpine` com `--network container:kamba-m3g-chromium`:

```js
// Instrumento do KAM-206: conduz o Chromium pela CDP (localhost:9222, a rede do
// contentor do Chromium) e mede o GET de uma pagina do painel com o perfil «3G»
// das DevTools e a CPU limitada a 4x, cache desligada. Uma linha JSON por corrida.
//   node condutor.mjs <url> <corridas>
import { readFileSync } from "node:fs";

const [url = "http://painel3g:3003/painel/produtos", corridasTxt = "5"] = process.argv.slice(2);
const corridas = Number(corridasTxt);
const cookie = readFileSync("/m/cookie.txt", "utf8").trim();
const PERFIL = { offline: false, downloadThroughput: 188_743, uploadThroughput: 86_400, latency: 562.5, packetLoss: 0 };

const versao = await (await fetch("http://127.0.0.1:9222/json/version")).json();
const ws = new WebSocket(versao.webSocketDebuggerUrl);
await new Promise((ok, mal) => { ws.onopen = ok; ws.onerror = mal; });
let proximo = 0;
const pendentes = new Map();
const ouvintes = [];
ws.onmessage = (m) => {
  const d = JSON.parse(m.data);
  if (d.id !== undefined && pendentes.has(d.id)) {
    const { ok, mal } = pendentes.get(d.id);
    pendentes.delete(d.id);
    d.error ? mal(new Error(JSON.stringify(d.error))) : ok(d.result);
  } else for (const f of ouvintes) f(d);
};
const cdp = (method, params = {}, sessionId) =>
  new Promise((ok, mal) => {
    const id = ++proximo;
    pendentes.set(id, { ok, mal });
    ws.send(JSON.stringify({ id, method, params, ...(sessionId ? { sessionId } : {}) }));
  });
const esperar = (method, sessionId) =>
  new Promise((ok) => {
    const f = (d) => {
      if (d.method === method && d.sessionId === sessionId) {
        ouvintes.splice(ouvintes.indexOf(f), 1);
        ok(d.params);
      }
    };
    ouvintes.push(f);
  });

console.log(JSON.stringify({ navegador: versao.Browser, url, perfil: PERFIL, cpu: 4 }));
for (let i = 0; i < corridas; i += 1) {
  const { targetId } = await cdp("Target.createTarget", { url: "about:blank" });
  const { sessionId } = await cdp("Target.attachToTarget", { targetId, flatten: true });
  await cdp("Page.enable", {}, sessionId);
  await cdp("Network.enable", {}, sessionId);
  await cdp("Network.setCacheDisabled", { cacheDisabled: true }, sessionId);
  await cdp("Network.emulateNetworkConditions", PERFIL, sessionId);
  await cdp("Emulation.setCPUThrottlingRate", { rate: 4 }, sessionId);
  await cdp("Network.setCookie", { name: "kamba_painel", value: cookie, url, secure: false, httpOnly: true }, sessionId);
  const carregada = esperar("Page.loadEventFired", sessionId);
  await cdp("Page.navigate", { url }, sessionId);
  await carregada;
  // O `loadEventEnd` so se escreve depois dos tratadores do `load`.
  await new Promise((ok) => setTimeout(ok, 300));
  const { result } = await cdp(
    "Runtime.evaluate",
    {
      expression:
        "JSON.stringify((function(){var n=performance.getEntriesByType('navigation')[0];return {estado:n.responseStatus,octetos:n.transferSize,corpo:n.decodedBodySize,ttfb:Math.round(n.responseStart),dcl:Math.round(n.domContentLoadedEventEnd),load:Math.round(n.loadEventEnd),formularios:document.forms.length};})())",
      returnByValue: true,
    },
    sessionId,
  );
  console.log(JSON.stringify({ corrida: i + 1, ...JSON.parse(result.value) }));
  await cdp("Target.closeTarget", { targetId });
}
ws.close();
```

`medir.sh`:

```sh
#!/bin/sh
# Instrumento do KAM-206: mede a lista de produtos (e a pagina de um produto) do
# painel em 3G simulado, antes (a publico/main) e depois (o ramo), seguidas.
#   medir.sh <arvore> <dir do instrumento> <corridas>
set -eu
ARVORE="$1"; M="$2"; N="${3:-10}"
REDE=kamba-m3g
export MSYS_NO_PATHCONV=1
docker network create "$REDE" >/dev/null 2>&1 || true
docker rm -f kamba-m3g-chromium painel3g >/dev/null 2>&1 || true
docker run -d --name kamba-m3g-chromium --network "$REDE" kamba-m3g-chromium \
  chromium --headless --no-sandbox --disable-gpu --disable-dev-shm-usage \
  --remote-debugging-port=9222 about:blank >/dev/null
servir() { # $1 = antes | depois
  docker rm -f painel3g >/dev/null 2>&1 || true
  if [ "$1" = antes ]; then
    EXTRA="-v $M/antes/pagina.ts:/w/services/onboarding-web/src/painel/pagina.ts:ro -v $M/antes/rotas.ts:/w/services/onboarding-web/src/painel/rotas.ts:ro"
  else EXTRA=""; fi
  # shellcheck disable=SC2086
  docker run -d --name painel3g --network "$REDE" -v "$ARVORE:/w" -v "$M:/m" $EXTRA \
    -w /w/services/onboarding-web node:24.21.0-alpine node /m/servidor.ts >/dev/null
  until docker logs painel3g 2>&1 | grep -q pronto; do sleep 1; done
}
conduzir() { # $1 = caminho
  docker run --rm --network container:kamba-m3g-chromium -v "$M:/m" node:24.21.0-alpine \
    node /m/condutor.mjs "http://painel3g:3003$1" "$N"
}
sleep 3
servir antes;  echo "== antes: /painel/produtos";        conduzir /painel/produtos
servir depois; echo "== depois: /painel/produtos";       conduzir /painel/produtos
               echo "== depois: /painel/produtos/sku-7"; conduzir /painel/produtos/sku-7
docker rm -f kamba-m3g-chromium painel3g >/dev/null
docker network rm "$REDE" >/dev/null
```
