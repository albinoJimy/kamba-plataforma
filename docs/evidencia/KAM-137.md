## 1. O ponto de partida

### 1.1 O *ruleset* efectivo lê-se, e a credencial que o lê

```
$ gh auth status
github.com
  ✓ Logged in to github.com account albinoJimy (keyring)
  - Token scopes: 'gist', 'read:org', 'repo', 'workflow'
```

```
$ gh api repos/albinoJimy/kamba --jq '.permissions.admin'

```

A credencial usada nesta medição é a sessão `gh` do fundador, que tem
administração do repositório. **Não é a credencial que o ADR desenha**: o ADR
pede um *fine-grained token* com `Administration: Read-only` e nada mais, e
criá-lo é acto do fundador. O que se mediu aqui vale para o caminho de leitura;
que o caminho funcione com uma credencial **só** de leitura fica
**NÃO VERIFICADO**, e valida-se criando o *token* do ADR, exportando-o em
`KAMBA_RULESET_TOKEN` e correndo `make ruleset TRANSPORTE=http`.

### 1.2 O espelho e o efectivo estavam iguais antes de se tocar em nada

```
$ gh api repos/albinoJimy/kamba/rulesets/24879081 --jq '{name,target,enforcement,conditions,rules,bypass_actors}'
```

## 2. O que se compara, e o que fica de fora

Da lista do critério 4, à letra. O código está em
`tools/ruleset_check/comparador.py`, e cada linha desta tabela tem teste.

| Comparado | Onde |
|---|---|
| `enforcement` (`active`) | `CAMPOS_DE_TOPO` |
| `name`, `target` | `CAMPOS_DE_TOPO` |
| `conditions` (`ref_name.include` / `.exclude`, ordem irrelevante) | `CAMPOS_DE_TOPO` |
| `bypass_actors` **vazio** | `CAMPOS_DE_TOPO` + regra própria |
| `rules.pull_request` — 8 parâmetros | `PARAMETROS_DE_POLITICA` |
| `rules.required_status_checks` — `strict_required_status_checks_policy`, `do_not_enforce_on_create`, e **os sete contextos** | `PARAMETROS_DE_POLITICA` |
| `rules.deletion` | `PARAMETROS_DE_POLITICA` |
| `rules.non_fast_forward` | `PARAMETROS_DE_POLITICA` |

**Os oito campos voláteis ignorados, nomeados um a um**, com a razão em
`comparador.VOLATEIS`:

| Campo | Porque não é política |
|---|---|
| `id` | identificador atribuído pelo GitHub; vive no `ci/ruleset.yaml`, não no espelho |
| `node_id` | identificador opaco da API GraphQL |
| `source` | o repositório de onde o *ruleset* vem; é contexto |
| `source_type` | `Repository` ou `Organization`; é contexto |
| `created_at` | carimbo de criação |
| `updated_at` | carimbo da última alteração; muda em edições que não mudam política |
| `current_user_can_bypass` | depende de **quem** pergunta: dois leitores vêem valores diferentes do mesmo *ruleset* |
| `_links` | hiperligações de navegação da API |

**Três propriedades que não estavam no critério e que fecham buracos da lista:**

- um campo de topo que a API passe a devolver e que **não esteja em nenhuma das
  duas listas falha** (`campo-novo-na-api`). Sem isto, uma política nova num
  campo novo entrava em silêncio;
- um campo de política **ausente dos dois lados** é divergência
  (`campo-de-politica-ausente`), e não «igual a si próprio»;
- um `bypass_actors` não vazio **no GitHub** é vermelho mesmo que alguém o
  acrescente também ao ficheiro. O ficheiro não é autoridade para conceder
  *bypass*.

**Dois valores comparados como estão, e não como «deviam ser»:**
`required_approving_review_count: 0` (cedência registada na lacuna 16 do
`../ci.md` §7) e `strict_required_status_checks_policy: false` (deliberado,
justificado no `README.md` do *ruleset*). O comparador compara o GitHub com o
ficheiro; não compara o ficheiro com uma opinião.

## 5. O procedimento da janela — para o fundador

**Isto executa-se de uma assentada, numa janela combinada, e repõe-se antes de
sair.** Entre o §5.2 e a sua reversão, e entre o §5.3 e a sua, o `main` do
`albinoJimy/kamba` fica menos protegido do que de costume: o §5.2 retira-lhe um
*required check* e o §5.3 dá *bypass* a quem tem administração. **Não correr com
um PR por fundir nem com uma automação de *merge* activa.**

Tudo o que se segue corre em Git Bash, da raiz do repositório, com o `gh`
autenticado numa conta com administração do `albinoJimy/kamba`. Onde está
`python`, use o mesmo interpretador que o `Makefile` usa (`PYTHON ?= python`,
`python3` em POSIX) — qualquer Python 3 serve, porque só se usa a biblioteca
padrão.

### 5.0 Antes de tocar em nada

```bash
# 1. a verificação tem de estar verde ANTES. Se não estiver, pare: já há
#    divergência, e o que ela diz é mais importante do que esta janela.
make ruleset

# 2. guardar o estado actual. É isto que repõe tudo, e é o artefacto de
#    rollback de toda a janela. Não apague este ficheiro até ao fim.
gh api repos/albinoJimy/kamba/rulesets/24879081 \
  --jq '{name,target,enforcement,conditions,rules,bypass_actors}' > ruleset-antes.json

# 3. conferir que o que se guardou é exactamente o espelho versionado.
#    Se isto imprimir "DIFERENTE", pare: o passo 1 estava a mentir.
python -c "import json;a=json.load(open('ruleset-antes.json',encoding='utf-8'));b=json.load(open('.github/rulesets/main.json',encoding='utf-8'));print('IGUAL' if a==b else 'DIFERENTE')"
```

**Esperado:** `make ruleset` sai **0** («conforme: 7 required check(s)…») e o
passo 3 imprime `IGUAL`.


## 6. O que se mediu de passagem, e que não é deste ticket

### 6.1 O repositório público não tem *ruleset* nenhum

```
$ gh api repos/albinoJimy/kamba/rules/branches/main --jq '[.[].type]'
["pull_request","required_status_checks","deletion","non_fast_forward"]

$ gh api repos/albinoJimy/kamba-plataforma/rules/branches/main
[]

$ gh api repos/albinoJimy/kamba-plataforma/rulesets
[]

$ gh api repos/albinoJimy/kamba-plataforma --jq '{visibility,permissions:.permissions.admin}'
{"visibility":"public","permissions":true}
```

O `[]` não é falta de permissão: a mesma conta tem `admin: true` nos dois
repositórios, e o mesmo comando no `kamba` devolve as quatro regras.

**O `albinoJimy/kamba-plataforma` é público, é onde os PR deste ticket são
abertos, e não tem nenhuma das protecções que o `.github/rulesets/main.json`
descreve.** Nem PR obrigatório, nem *required checks*, nem protecção contra
apagar ou reescrever `main`. Criar lá um *ruleset* é **governação** e está fora
do âmbito deste ticket, que só podia nomear o facto; fica como **lacuna 29** do
`../ci.md` §7.

### 6.2 O `GITHUB_TOKEN` e a permissão `administration`

**NÃO VERIFICADO por execução.** É a razão que o ADR dá para a verificação não
ser um *gate*, e vale o que vale até ser medida. Como se valida: acrescentar
`permissions: {administration: read}` a um *workflow* de teste e ver se o GitHub
aceita o ficheiro; ou correr `gh api repos/albinoJimy/kamba/rulesets` dentro de
um *job* com o `GITHUB_TOKEN` e ler o código devolvido.

O que **está** medido é a outra metade do argumento: um *token* num *workflow*
exigiria uma referência `secrets.*`, e o `grep` do `../ci.md` §6 continua a
devolver zero porque **nenhum ficheiro de `.github/workflows/` foi tocado**
(§7.3).

### 6.3 A credencial do ADR não foi exercitada

A medição correu com a sessão `gh` existente, que tem administração completa.
